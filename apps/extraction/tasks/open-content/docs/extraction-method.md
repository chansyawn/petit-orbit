# 开放内容提取原理与独立实现指南

本文说明如何从客户端独立实现两份开放内容导出，不依赖本仓库脚本或执行命令。算法及字段位置在客户端 **0.95.2、配置 revision 1379138、资源 revision 1359983、清单目录 5662883** 上确认；换版本后重新验证。字段编号从零开始，不是恢复出的官方字段名。

## 范围与证据

根字段 93 的普通行向量包含 2,327 个唯一 ID。用户确认这些内容均已开放，包括没有进入万象列表的 51 个角色外观，以及作为大类内小分类的 67 个主题集合。这个结论只适用于该版本和该集合；表外的解锁卡、菜谱等不能因此判为未开放。

入口共 2,133 个单品、143 个套组、51 个外观。单品分类为家具 887、植物 202、生物 317、服饰 590、菜肴 121、杂物 16。套组为家具 42、服装 34、作物 17、花 14、鱼 11、昆虫 9、赶海生物 7、烹饪 9。外观为发型 23、眼睛 19、眉毛 8、面饰 1。不能使用图标是否存在决定内容是否保留。

两份数据使用同一入口名单。原始组保留全部关联记录的字段和字节，不猜测业务意义。语义化组只命名已确认字段；未知含义留在原始组。辅助记录与入口记录分开计数。

## 输入与版本选择

客户端根目录下的 `config.ini` 保存 `game_version`。配置位于 `PetitPlanet_Data/StreamingAssets/GenerateAssets`、`Persistent/GenerateAssets` 或 `Persistent/Temp/<清单目录>/GenerateAssets`，文件为 `ed.obb` 与 `cs.obb`。不能只读取基础配置。当前完整匹配位置是 `Persistent/Temp/5662883/GenerateAssets`。

读取 `Persistent/versions/<清单目录>/data_revision.json`、`res_revision.json` 与对应的 `data_versions.json`、`res_versions.json`。后两者实际是 CSV，表头为 `FilePath,md5,FileSize`。核对分支 `live_0.95`、各 revision、文件大小及 MD5；只采用同一清单中两份 OBB 都匹配的配置对。另存 SHA256、客户端内相对路径和所选清单，不能将本地校验结果称为线上最新版本。

Asset Map 需要覆盖基础与更新资源，保留 `Type`、`Name`、`Container`、`PathID`、`Source`。PathID 作为字符串保存，避免 64 位整数精度损失。XML 实体需要解码；Source 按 `PetitPlanet_Data/` 后的路径重定位到当前客户端。不要只扫描名字包含 item 的资源。分类还需要从更新数据包 `Persistent/AssetBundle/blocks/00/00000002.blk` 读取名为 `633e15d6` 的 MiHoYoBinData JSON，当前 SHA256 为 `d0a37c7ca44f94615a6e19530722e275fda1c1cbb5defb1af593a8c2ac68f851`，包含 948 个 GameplayTag 节点。

## 字节解码与结构遍历

OBB 采用变形的 FlatBuffers 布局。下列地址都是文件字节偏移：

```text
u32(p) = unsigned32(read_uint32_big_endian(p) XOR 0x53020253)
i32(p) = reinterpret_signed32(u32(p))
u16(p) = read_uint16_big_endian(p) XOR 0x5555
ref(p) = p + u32(p)
```

长度为 n 的编码字节数组解码如下。长度使用字节数；长字符串必须保留 n 的高位，奇数中心使用 mask[0]。

```text
key = unsigned32(n XOR 0x01350257)
mask = [key & 255, (key >> 8) & 255, (key >> 16) & 255, key >> 24]
for i in 0 .. n-1:
    j = n-1-i
    k = 0 if i == j else min(i,j) modulo 4
    decoded[j] = encoded[i] XOR mask[k]
```

固定宽度标量也可使用此变换后按小端读取：单字节读 uint8，四字节浮点读 float32 little-endian。表 93 字段 1 必须按 **一字节**读取；字段 17 是 **float32**，当前约 0.8，不能将其位模式解释为整数参数。

文件根对象地址为 `u32(0)`。对象 t 的 `vtable = t - i32(t)`；有符号偏移可能使 vtable 位于对象后方。vtable 首两项 u16 为其字节长度 L 与对象字节长度 S。第 k 个字段的相对地址为 `u16(vtable+4+2*k)`，零表示没有写入。检查 L 为偶数且至少 4、vtable 与整个对象在文件范围内、非零偏移严格小于 S。不要为缺省字段补零。

普通集合路径为：根字段 → 引用到包装对象 → 包装字段 0 → 引用到行向量 v。`u32(v)` 是行数；第 i 行对象地址为 `ref(v+4+i*4)`。先检查整个引用数组范围，再遍历各行。根字段 1 是字典，不适用普通行向量布局。

字符串字段地址 p 指向 `s=ref(p)`，`n=u32(s)`，编码载荷位于 `s+4`。验证范围和合理长度后解码 n 字节，再使用严格 UTF-8 解码，拒绝非法控制字符。长度零是显式空字符串，不等于缺省字段。

**不能试解引用所有数字并把成功结果当成字符串。** 一些数字恰好指向其他对象的合法图片字符串。必须以已验证的存储类型白名单解码，其余字段保留字节。相邻字段间距只表示包含填充的存储区间，不证明标量宽度。

### TextMap

根字段 1 → 包装对象字段 0 → 字典对象。字典字段 0 为数量，3 为哈希桶向量，4 为文本记录引用向量。桶每项 8 字节，文本引用每项 4 字节：

```text
bucket = read_uint64_little_endian(decode_8_bytes(encoded_bucket))
low = bucket AND 0xffffffff
if low == 0xffffffff: skip empty bucket
hash = bucket >> 32
index = low >> 8
row = ref(values_vector + 4 + index*4)
```

验证索引范围、哈希唯一性以及有效桶数等于字典数量和文本行数。当前 116,673 条文本，233,343 个桶。文本记录字段 0–14 都是字符串，依次为英、简中、繁中、法、德、西、葡、俄、日、韩、泰、越、印尼、土耳其、意大利语。原始组保留引用文本的所有语言及桶字节；语义化组使用简中和英文。可选描述哈希缺失时留空并记录未解析清单；入口名称、分类名称缺失则停止。

## 图片关联与导出

收集 325 的 4/5/6、186 的 11、93 的 22、33 的 9/10 以及辅助卡的显示图片。没有引用与有引用但未索引分别记录。未知数值偶然解引用出的图片不能加入清单。

路径统一转小写、反斜线转斜线，去 `.png/.jpg/.jpeg/.tga/.psd` 后缀；当前 Container 前缀为 `assets/moleres/rel/sres/`。先按完整 Container 匹配 Texture2D；没有 Texture2D 或其名称为 sactx 图集时，按完整 Container 加引用文件名匹配 Sprite。不能只按名字、物品 ID 前缀或相似路径选择。保留基础与更新来源候选，优先 Persistent；同优先级有不同资源身份时停止。

资源身份为来源包、对象类型、PathID。每个身份独立命名 PNG，不按 Container 哈希假设对象唯一。同一包存在同名对象时分别按精确名字和 Container 导出，避免输出文件覆盖。导出选中的图片失败必须停止，不能改写为无图。PNG 必须完整解码并检查 CRC、尺寸、SHA256。

所有实际来源包先核对清单大小和 MD5，同时计算 SHA256。基础包使用 StreamingAssets 的 res 清单，Persistent 包优先使用更新 data 清单再使用更新 res 清单。图标可优先使用已匹配小图，否则使用已匹配大图；其他图片同时保留，不作为图标替代。

## 输出与验收

原始记录保存表号、行偏移、对象与 vtable 原始十六进制字节、各字段显式存在状态、存储区间字节、已确认类型和值、已确认引用的长度头及载荷字节。未知引用不展开；其源偏移和配置 SHA256 可供重新调查，原始组不是完整客户端备份。

语义记录提供名称、类型、白名单标签、角色、分类、开放依据、说明、生物介绍、奖励与卡关联、图片状态及原始定位。字段来源映射说明每个命名值来自哪个表字段或计算规则。两组都携带素材、引用映射、缺失清单和来源校验结果，辅助定义不增加入口数量。

验收包括入口 ID 一致性、上述分类与角色计数、所有 2,327 条主物品关联、317 个生物关联、143 个套组奖励（14 个不同奖励 ID）、47 个外观卡关联、原始字节与源文件一致、图像全量解码及两个素材副本哈希一致。

当前基础图标覆盖 2,317 条，涉及 2,247 个不同资源；这不是全部图片数。没有显示配置的 ID 为 95014、95015、95016、95113、95114；主图引用未索引的 ID 为 52、53、54、2210、2211。集合图像有复用家具图标的情况，不能据此推断其专属封面。其他图片缺失数量按实际引用清单统计。

新版本先核对完整配置对与 Asset Map 范围，再重新定位根表、检查主关联 ID、字段宽度和引用类型，重新提取标签树并复现子项名单。数量不一致应定位差异，不通过增删 ID 或猜测字段使结果凑齐。
